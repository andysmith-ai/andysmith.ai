The problem of distractions during short pauses is far from new. Compilation used to fill these pauses, then CI and tests, and now it is the time spent waiting for an AI agent to respond.

When I give an AI agent a task and it starts thinking, it is tempting to switch to another task, or just scroll through a feed. This is dangerous because frequent context switching is costly, and by the end of the day I start to feel exhausted. It can also make me forget to return to the original task after switching to something new.

I notice this problem in myself and am looking for a solution. Naturally, the solution lies in habits and technology that support my daily process.

The main rule I try to follow is one task at a time. This means that if my task is to finish the agent platform until I reach some first tangible result, I should not get distracted by anything else. Everything else is waste, in Lean Manufacturing terms, because it increases the amount of unfinished work instead of reducing it.

The approach to use here has been known for a long time. I take a final task, preferably not a very large one, set a deadline, and complete it by then. As we know, a task can take all the time allotted to it. See <https://en.wikipedia.org/wiki/Parkinson%27s%5FLaw>. So the deadline should be roughly proportional to the expected result. This comes with experience. And, of course, agents should do this for me. No manual timesheets or plans.

The question of what to do during pauses remains open. I think my approach to asynchronous work through email may help here. Instead of waiting for an agent to respond, I can keep writing in new sessions, or add something to an existing one, without worrying that a new response from the agent will change anything. My reply will contain a link to the message I am responding to, so the agent will understand that I wrote it without the context of its latest response. This is a free bonus that comes with working through email.
